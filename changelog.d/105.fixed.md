Harden the zero-allocation conversion path and the review findings around it: the metrics store opens its database with `SQLITE_OPEN_NOFOLLOW` and saturates byte counters instead of overflowing; a failed encode is reported as `EncodeFailed` rather than a round-trip mismatch; case-insensitive input resolution no longer replaces a precise "not found" with a directory permission error; and the Codex hook emits `continue: false` alone, since `decision: "block"` rejects the tool call instead of replacing its result.

Pin `cargo-rail` to 0.21.0 in CI. Version 0.22.0 removed the `rail run` subcommand that every change-detection step uses, so unpinned installs broke `Check`, `Test` and `Documentation` on every branch including `main`.

Resolve the ledger's parent directory before that `SQLITE_OPEN_NOFOLLOW` open. The flag refuses a symbolic link anywhere in the path, not just the database file, and macOS reaches its temporary directory through `/var`, itself a link to `private/var`. Every macOS ledger therefore failed to open and silently recorded nothing, because `pipe` treats metrics as best-effort. Only the directory is resolved, so the flag still guards the database file itself.
